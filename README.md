# Клиентский бриф МСДИС

Интерактивный сервис для сбора требований к проектам заказной разработки и автоматизации бизнес- и производственных процессов. Администратор описывает известный контекст, CloseRouter формирует персональные архитектурно значимые вопросы, а клиент отвечает по закрытой ссылке в удобном темпе.

## Возможности

- Русскоязычный адаптивный интерфейс в стиле брендбука МСДИС: фирменный синий `#306DFA`, светло-голубые `#D0DEFD` / `#E8EEFE`, графит `#31323F`, типографика Manrope.
- Административный кабинет с авторизацией, списком брифов, статусами и прогрессом, просмотром ответов и файлов.
- Уникальные непредсказуемые ссылки для клиентов. Пароль не нужен: ссылку можно открыть только имея сам секретный URL. Создать дополнительные ссылки можно из кабинета.
- CloseRouter API: `https://api.closerouter.dev/v1/chat/completions` с Bearer-ключом и OpenAI-совместимым форматом. По умолчанию выбрана `anthropic/claude-sonnet-5.5`; модель можно сменить на любой доступный публичный model ID через `CLOSEROUTER_MODEL` или каталог CloseRouter.
- Генерируемые форматы: текст, развернутый ответ, один/несколько вариантов, шкала, да/нет, файл. Вопросы не обязательны; клиент может пропускать, перемещаться между ними и возвращаться позже.
- Автосохранение ответов в SQLite; прогресс и ссылка сохраняются после закрытия страницы. Клиент может отметить бриф завершённым и продолжить редактирование позднее.
- Прикрепление до 5 файлов за раз, до 15 МБ каждый. Файлы доступны только по ссылке брифа или администратору.
- Если CloseRouter API не настроен или временно недоступен, сервис сохраняет бриф и показывает клиенту проверенный набор вопросов по архитектуре.
- Docker-образ и Compose, SQLite и файлы хранятся в persistent volume.

## Быстрый запуск в Docker

Требуются Docker Engine и Docker Compose plugin. В каталоге приложения:

```bash
cp .env.example .env
```

Задайте в `.env` уникальный пароль и секрет сессии (не оставляйте примеры):

```bash
openssl rand -hex 32
```

Скопируйте созданное значение в `SESSION_SECRET`, задайте надёжный `ADMIN_PASSWORD`, а также API-ключ CloseRouter в `CLOSEROUTER_API_KEY`. Затем:

```bash
docker compose up -d --build
docker compose logs -f
```

Проверить запуск: `docker compose ps`. Приложение слушает порт `4000`. Подключите reverse proxy веб-сервера/контейнерной платформы к `http://127.0.0.1:4000` или внутреннему адресу контейнера и привяжите нужный HTTPS-поддомен. Передайте прокси исходные заголовки `Host`, `X-Forwarded-For`, `X-Forwarded-Proto`; HTTPS обязателен, так как `COOKIE_SECURE=true`.

Пример минимального Nginx location:

```nginx
location / {
    proxy_pass http://127.0.0.1:4000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 20m;
}
```

Откройте `https://ваш-поддомен/` и войдите в кабинет по `ADMIN_PASSWORD`. Данные лежат в `./data` на хосте. Для резервной копии остановите контейнер и сохраните папку `data` целиком. Обновление после получения кода: `git pull` (в нужной ветке), затем `docker compose up -d --build`.

> При первом развёртывании production рекомендуем запускать за HTTPS reverse proxy и ограничить доступ к административной части на уровне корпоративного SSO/VPN, если домен публичный. Ссылка клиента действует как bearer-секрет: пересылайте её только адресату.

## Локальная разработка

Требования: Node.js 22+, npm.

```bash
npm ci
cp .env.example .env
# задайте ADMIN_PASSWORD, SESSION_SECRET, CLOSEROUTER_API_KEY
NODE_ENV=development COOKIE_SECURE=false npm run dev
```

Vite: `http://localhost:5173`, API: `http://localhost:4000`. Команда отключает Secure-cookie только для локальной разработки по HTTP; для production используйте Docker Compose и HTTPS. База и загрузки создаются в `data/`.

## Тестирование и сборка

```bash
npm test
npm run typecheck
npm run build
```

Тесты проверяют защиту административных маршрутов, создание брифа, закрытые ссылки, автосохранение/возобновление, выдачу дополнительных ссылок, загрузку файлов, закрытость загрузок и завершение брифа.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `ADMIN_PASSWORD` | Пароль администратора (обязателен для входа) |
| `SESSION_SECRET` | Секрет подписи cookie сессии администратора; минимум 32 случайных байта |
| `CLOSEROUTER_API_KEY` | Ключ API CloseRouter; без ключа используется локальный набор вопросов |
| `CLOSEROUTER_MODEL` | ID модели из каталога CloseRouter; по умолчанию `anthropic/claude-sonnet-5.5` |
| `COOKIE_SECURE` | `true` для production HTTPS |
| `PORT` | Порт HTTP сервера (по умолчанию 4000) |
| `DB_PATH` | Путь SQLite (по умолчанию `data/briefs.sqlite`) |
| `UPLOAD_DIR` | Каталог вложений (по умолчанию `data/uploads`) |

## Модель и обработка данных

Модель выбирается через `CLOSEROUTER_MODEL`; текущий default — `anthropic/claude-sonnet-5.5`. Сверяйте актуальные модели, поддерживаемые endpoint-ы и цены в [каталоге CloseRouter](https://closerouter.dev/models). Интеграция использует официальный OpenAI-совместимый `POST /v1/chat/completions` endpoint. Перед отправкой реальных клиентских данных проверьте правила хранения и обработки данных CloseRouter и выбранного модельного провайдера. Передавайте только сведения, которые разрешено обрабатывать внешним AI-провайдерам. API-ключ хранится только в переменной окружения сервера и браузеру не передаётся.
